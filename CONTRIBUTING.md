# Как вносить изменения в документацию

Документация UzCloud ведется в Markdown и версионируется в git. Каждое изменение оформляется через pull request.

## Структура

- `ru/`, `uz/`, `en/` — языковые версии. **Структура каталогов и имена файлов во всех трех языках одинаковые**: страница `ru/compute/compute-instance.md` соответствует `uz/compute/compute-instance.md` и `en/compute/compute-instance.md`.
- `images/` — скриншоты, общие для всех языков. Ссылки на изображения — относительные (например, `../../images/instance.png`).
- `<язык>/README.md` — оглавление языковой версии. При добавлении, удалении или переименовании страницы обновите оглавление во всех трех языках.

## Оглавление — источник навигации

Сайт документации строит меню **только по оглавлению** `<язык>/README.md`: названия разделов и групп, порядок статей и вложенность берутся оттуда. Названия папок на сайте не используются, поэтому папка `sdk/` называется в меню «Работа из кода», а папка `buckets/` — «Работа с бакетами».

Оглавление начинается после первого заголовка второго уровня (`## Содержание`) и состоит только из строк четырех видов:

```markdown
### Объектное хранилище (Ceph)                              ← раздел

- [Создание объектного хранилища](object-storage/create-object-storage.md)   ← статья раздела
- **Работа с бакетами**                                     ← группа (жирным, без ссылки)
  - [Версионирование объектов](object-storage/buckets/versioning.md)         ← статья группы
```

Правила:

- раздел — заголовок `###`; группа — пункт списка, выделенный жирным, без ссылки; статья — пункт списка со ссылкой на `.md`-файл;
- статья группы пишется с отступом в два пробела; глубже групп вложенности нет;
- после группы можно продолжить статьи раздела без отступа — они уже не входят в группу;
- каждая статья указана в оглавлении ровно один раз, и каждая страница языковой версии есть в оглавлении;
- структура оглавления (разделы, группы, порядок и пути статей) во всех трех языках одинаковая — отличаются только названия.

## Правила

1. **Меняете содержание — меняйте все три языка в одном pull request.** Если перевода пока нет, добавьте английский текст в остальные версии и отметьте это в описании PR.
2. **Названия элементов интерфейса** (кнопки, вкладки, поля) пишутся **жирным** и так же, как в консоли. Пока интерфейс консоли только на английском, в русской и узбекской версиях они остаются на английском; при необходимости перевод дается в скобках: `**Submit**`, `**Zone** (зону)`.
3. **Узбекский язык** — латиница с символами `oʻ`, `gʻ` (U+02BB) и `ʼ` (U+02BC), например `maʼlumot`, `oʻrnatish`.
4. **Выделенные блоки** — в формате GitHub: `> [!TIP]`, `> [!NOTE]`, `> [!WARNING]`.
5. **Ссылки между страницами** — относительные, на `.md`-файлы.
6. **Бренд** — только UzCloud; адрес консоли — `https://console.uzcloud.uz`.
7. **Буква «ё»** в русском тексте не используется («развертывание», «объем», «ее»), кроме слов, где без нее меняется смысл: «всё» (в отличие от «все»).

## Скриншоты

Скриншоты сняты в [console.uzcloud.uz](https://console.uzcloud.uz) с английским интерфейсом и светлой темой, окно браузера 1440×900, в масштабе 1:1. При обновлении скриншота:

- сохраняйте то же имя файла в `images/` — тогда ссылки менять не нужно;
- не показывайте на скриншотах персональные данные, реальные IP-адреса, ключи и пароли: используйте имя «UzCloud Demo», почту demo@uzcloud.uz и адреса из документационных диапазонов (`203.0.113.0/24`, `198.51.100.0/24`);
- снимайте формы с демонстрационными значениями и не отправляйте их, если это создает платный ресурс;
- формат — PNG, ширина до ~1600 px.

## Проверка перед pull request

Запустите проверку локально (нужен только Python 3):

```bash
python3 scripts/check-docs.py
```

Скрипт проверяет формат оглавления и его совпадение во всех языках, что каждая страница есть в оглавлении, одинаковый набор страниц и изображений в языковых версиях, ссылки, якоря и изображения, неиспользуемые файлы в `images/` и правило буквы «ё». Та же проверка автоматически запускается в GitLab CI для каждого merge request и для ветки `main`: merge request с ошибками не пройдет проверку.
