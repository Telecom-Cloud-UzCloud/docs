# VNF-устройства

## Устройства виртуальных сетевых функций (VNF)

**Виртуальные сетевые функции (VNF)** — это программные приложения, которые предоставляют сетевые сервисы: маршрутизаторы, межсетевые экраны, балансировщики нагрузки, WAN-оптимизаторы. В отличие от традиционных аппаратных сетевых устройств, VNF работают на виртуализированной инфраструктуре, что обеспечивает гибкость, масштабируемость и экономическую эффективность.

**UzCloud** упрощает развертывание VNF-устройств и управление ими, позволяя масштабировать и адаптировать сетевую инфраструктуру под потребности. В этом руководстве описано, как создать VNF-устройство в **UzCloud**.

---

### Создание VNF-устройства

- В меню слева откройте вкладку **VNF Appliances**.
- Откроется страница **VNF Appliances**.

![Страница VNF Appliances](../../images/create-vnf-app.png)

- Чтобы создать VNF-устройство, нажмите **Create VNF Appliances** или значок **плюс (+)** в правой части страницы. Откроется страница создания VNF-устройства.

### Выбор расположения

- Выберите дата-центр, в котором будет физически размещено устройство.
- Выберите одно из доступных расположений.

![Выбор расположения](../../images/create-instance-location.png)

### Выбор образа

- Выберите операционную систему или шаблон приложения для установки.
- Доступны популярные образы ОС. Также можно импортировать собственный ISO-образ.
- **Примечание**: для Microsoft Windows доступны только официальные ознакомительные (evaluation) версии.

![Выбор образа](../../images/create-instance-choose-images.png)

### Выбор типа выделения CPU

- Выберите тип выделения процессорных ресурсов, подходящий для вашей нагрузки:

![Выбор типа CPU](../../images/create-instance-choose-type.png)

- **Shared CPU** — недорогой вариант, ресурсы разделяются между пользователями. Подходит для разработки, тестирования и нетребовательных нагрузок, например небольших сайтов.
- **Dedicated CPU** — выделенные ресурсы для стабильной производительности. Подходит для продуктивных сред, высоконагруженных приложений и баз данных.
- **High-Frequency Compute** — высокая тактовая частота для ресурсоемких вычислений: моделирования, финансовых расчетов и приложений, чувствительных к задержкам.
- **Cloud GPU** — GPU-ускорение для требовательных задач: машинного обучения, ИИ, рендеринга видео и научного моделирования.

### Выбор тарифного плана

- Выберите план в соответствии с требованиями к CPU, памяти, хранилищу и пропускной способности. При необходимости можно создать собственный план.

![Выбор плана](../../images/create-plan-vnf-app.png)

- **General Compute (GC)** — для сбалансированных нагрузок с сочетанием CPU, памяти, хранилища и пропускной способности. Подходит для приложений общего назначения, веб-серверов и тестовых сред.

### Привязка к проекту

- Привяжите устройство к одному из ваших проектов, чтобы удобно организовывать ресурсы и управлять ими.

![Привязка к проекту](../../images/create-instance-choose-project.png)

### Выбор сети

- Выберите сеть в зависимости от требований к подключению и безопасности. Подробнее о доступных вариантах сетей см. в соответствующих руководствах.
- Чтобы подключить устройство к существующей сети, выберите ее из списка доступных.

![Выбор сети](../../images/create-networks-vnf-app.png)

- **Public Network** — простая преднастроенная сеть для внешнего подключения. Включает облачный межсетевой экран, проброс портов и VPN удаленного доступа. Подходит тем, кому нужно простое подключение без лишних настроек.
- **VPC Network** — продвинутое сетевое решение с полным контролем над маршрутизацией трафика и повышенной безопасностью. Поддерживает VPN-шлюз, VPN-соединения site-to-site и разделение трафика.

**Примечание:** по умолчанию VPC создается со случайным блоком **CIDR** и одним сетевым уровнем (tier).

- Вы можете включить публичный IPv4-адрес для доступа к устройству из интернета.

![Включение публичного IP](../../images/create-instance-enable-public-ip.png)

### Выбор группы привязки

- Выберите группу привязки (Affinity Group) или создайте новую, нажав **Create Affinity Groups**.

![Выбор группы привязки](../../images/select-ag.png)

### Настройки сервера

- Настройте дополнительные параметры.
- Можно **добавить SSH-ключ** для безопасного доступа. Нажмите **Add Now**, чтобы добавить SSH-ключ.
- **Примечание**: для некоторых образов ОС, например Arch Linux, SSH-ключ обязателен, так как вход по паролю не поддерживается.

![Добавление SSH-ключа](../../images/create-instance-add-ssh.png)

- Укажите имя SSH-ключа и его значение, затем нажмите **Add SSH Key**.

![Данные SSH-ключа](../../images/create-instance-add-ssh-kay.png)

- Добавьте скрипт запуска, чтобы автоматизировать действия при инициализации. Нажмите **Add Now**, чтобы добавить скрипт запуска для устройства.

![Добавление скрипта запуска](../../images/create-instance-add-startup-script.png)

### Расширенные настройки (необязательно)

- Включите **Advanced Mode**, чтобы задать дополнительные параметры ВМ для оптимизации производительности, безопасности и гибкости.

![Расширенные настройки](../../images/create-instance-advance-mode.png)

- **Boot Mode** — выберите Legacy или Secure boot для защиты процесса загрузки.
- **Boot Type** — выберите UEFI (современная прошивка) или BIOS (традиционная прошивка).
- **Enable Dynamic Scaling** — позволяет автоматически масштабировать ресурсы в зависимости от нагрузки.

### Имя сервера

- Укажите уникальное **Server Name** и корректное **Server Hostname**, чтобы легко находить устройство в панели управления.

![Имя хоста сервера](../../images/create-instance-server-hostname.png)

### Проверка и развертывание

- Выберите нужный **Billing Cycle**. Для VNF-устройств поддерживаются периоды: почасовой, ежемесячный, ежеквартальный, раз в полгода, ежегодный, раз в два года и раз в три года.
- Поддерживаются все основные правила биллинга: Date to Date, Fixed Calendar Month, Unfixed Calendar Month, Fixed Prorata и Unfixed Prorata.
- Доступны разные пакеты в зависимости от размера SSD и расположения дата-центра — это позволяет развертывать сетевые функции с учетом региона и требований к производительности.
- Проверьте все параметры и итоговую стоимость. Нажмите **Review & Deploy**, чтобы создать устройство.

![Проверка и развертывание](../../images/create-instance-depoly.png)

### Заключение

Следуя этому руководству, вы легко создадите VNF-устройства в UzCloud и сможете управлять ими. VNF-устройства — гибкое и масштабируемое решение для развертывания сетевых сервисов в виртуализированной среде. Если нужна помощь, изучите документацию UzCloud или обратитесь в поддержку.
